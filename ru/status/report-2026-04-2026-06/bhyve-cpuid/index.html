Полное управление CPUID для bhyve

Контактное лицо: Hans Rosenfeld <rosenfeld@grumpf.hope-2000.org>

Обзор проекта

Текущая работа над этим проектом направлена на интеграцию существующей концептуальной реализации во FreeBSD и добавление следующих функций удобства использования:

  • удобный метод настройки для переопределения отдельных битов, частей или даже целых функций CPUID по мере необходимости с сохранением остальной информации о CPUID хоста или предварительно заданной конфигурации CPUID;

  • удобный метод настройки идентификатора гипервизора, сообщаемого bhyve;

  • набор предварительно заданных конфигураций CPUID на основе общих архитектурных уровней x86, возможно, также включающий набор данных CPUID для нескольких реальных моделей процессоров, и удобный метод настройки для выбора одного из них для виртуальной машины.

Изменения в течение последнего квартала

Расширения синтаксиса конфигурации bhyve

Существующий синтаксис файла конфигурации bhyve был ограничен присваиваниями узлам конфигурации, которые внутренне преобразовывались в древовидный набор списков nvlist.

Чтобы обеспечить более гибкую настройку с использованием предварительно заданных фрагментов файлов конфигурации, синтаксис файла конфигурации bhyve был дополнен двумя новыми возможностями:

  • В узел конфигурации можно добавить значение с помощью оператора +=. Если этому же узлу конфигурации уже было присвоено значение, новое значение добавляется к старому, разделяясь запятой.

  • Другой файл конфигурации можно включить с помощью директивы include. Поддерживаются абсолютные и относительные пути, но относительные пути интерпретируются как относительные к пути файла конфигурации, в котором находится директива включения.

Ещё более гибкая настройка CPUID

Механизм настройки CPUID был расширен для поддержки символических имён возможностей, где каждое имя соответствует определённому биту регистра для функции CPUID. Это особенно полезно для отдельных расширений системы команд или других опциональных возможностей, которые можно включать или отключать по желанию.

Таким образом, вместо настройки cpuid.0x00000001+=edx|=0x00040000 теперь можно просто написать cpuid.enable+=psn. Существует также соответствующая опция cpuid.disable для символических возможностей.

Использование битовых операций над регистрами CPUID, конечно, всё ещё поддерживается, поскольку не все возможности CPUID могут быть выражены в виде отдельных битов возможностей.

Использование архитектурных уровней x86

Архитектурные уровни x86 теперь реализованы как набор предварительно заданных фрагментов файлов конфигурации, причём каждый более высокий уровень строится поверх более низкого.

Чтобы проиллюстрировать это, вот как теперь выглядит x86-64-v3.cfg:

include x86-64-v2.cfg
cpuid.enable+=fma,movbe,osxsave,avx,f16c
cpuid.enable+=bmi1,avx2,bmi2
cpuid.enable+=abm

Модель процессора или архитектуры можно выбрать либо путём включения соответствующего файла конфигурации из /usr/share/bhyve/cpu в файл конфигурации bhyve, либо указав её в командной строке как часть конфигурации виртуального процессора: bhyve […​] -c 16,model=x86-64-v1 […​]

Ограничения CPUID

Чтобы предотвратить случайное включение возможностей CPUID для гостевого процессора, которые не поддерживаются хост-процессором, анализатор конфигурации CPUID был расширен списком ограничений CPUID, которые проверяются при установке или изменении значения определённого регистра CPUID.

Для любого регистра в функции CPUID ограничение может указывать, какие биты неизменяемы, а какие могут быть только очищены.

Ограничения проверяются после применения конфигурации CPUID.

Планы на следующий квартал

  • Реализовать переопределения для ограничений CPUID, чтобы игнорировать любые ограничения или предупреждать о нарушении ограничения вместо остановки настройки виртуальной машины.

  • Предоставить больше предварительно заданных конфигураций процессоров на основе реальных процессоров.

  • Аналогично установке архитектурного уровня x86, будет реализован механизм для переопределения идентификации гипервизора без необходимости ручного изменения битов CPUID.

  • Провести рецензирование всего набора изменений и включить его во FreeBSD.
